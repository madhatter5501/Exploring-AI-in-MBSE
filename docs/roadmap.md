# Research roadmap

*Working sequence, not a delivery commitment*

This is an independent research investigation. The work should earn each new layer of complexity through evidence.

| Stage | Smallest useful output | Decision |
|---|---|---|
| **0 — Historical escapes** | 20–30 cases classified against an as-of-time graph; confidence and exclusions reported | Is missing traversal actually a major failure mode? |
| **1 — Prior art / build-vs-buy** | Capability matrix for existing MBSE tools, graph queries, policy systems, Codex-style and managed agents | Which gaps remain genuinely unmet? |
| **2 — Minimal contract** | Frozen roots, scope, graph obligation enumerator, and per-node inspection schemas without an LLM | Can the contract detect vacuous “coverage”? |
| **3 — Agent experiment** | Same dataset and gates, with optional probabilistic analysis | Does it add useful interpretation at acceptable cost? |
| **4 — Authorization & consent** | Exact-action reviews, waiver roles, cross-action risk analysis, deny-path tests | Do users remain meaningfully in control? |
| **5 — Human study** | Reviewer accuracy, automation bias, net value and baseline comparison | Does the system reduce total error, or merely make output look authoritative? |

## Working decision gates

- **Stop / reframe** if dependencies are usually absent from the historical model, or accessible historical baselines do not exist.
- **Use existing tooling** if standard queries, checklists, and policy/approval engines satisfy the actual assurance requirement.
- **Keep it domain-specific** if the hard part is engineering semantics and not portable harness infrastructure.
- **Consider building a general-purpose layer** only when independent tests show a repeated, cross-domain unmet contract.
- **Avoid a safety/product claim** without relevant qualification, engineering evidence, and operational controls.

## Contributions especially useful now

1. Prior art that already implements the proposed contract.
2. An anonymizable engineering-escape case with an authentic historical graph baseline.
3. A counterexample where a “fully verified” graph inspection is still materially wrong.
4. Practical feedback on SysML v2 import, semantic validation, and requirement-to-test coverage.
5. Evidence that a thin verifier or existing platform is superior.
